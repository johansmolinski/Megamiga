# Megamiga on the MEGA65 R3/R3A (no SDRAM)

Status: in development (branch `r3`, started 2026-11-03 on top of `chipfix`); first bitstreams built, not yet on hardware.

## Why R3 needs its own memory design

R4/R5/R6 keep all Amiga memory in the board SDRAM (`amiga_sdram.vhd` + Minimig's
`sdram_ctrl.v`). The R3 and R3A have no SDRAM: only the FPGA's block RAM and the 8 MB
HyperRAM, which the HDMI scaler (ascal) also uses.

Measured with the Apidya full-system bench (`~/aexp-work/hyperr3/bus`: Minimig + fx68k +
floppy engine, the RAM model delivering read data N core clocks after the address):

- Minimig's chip bus makes one access per 7 MHz cycle (4 core clocks, 141 ns); two chip RAM
  accesses 141 ns apart happen (about 98,000 times in 3 simulated seconds).
- Read data must be there 2 core clocks (~70 ns) after the address: N = 1 and 2 give a
  byte-identical run, N = 3 crashes. This matches `sdram_ctrl.v`, which delivers chip data at
  state 9 of 16 (~90-100 ns after the 7 MHz edge, the address appearing ~35 ns into it).

HyperRAM cannot meet this: a HyperBus access needs 3 clocks of command/address, the DRAM
row access (~35-40 ns), a doubled latency whenever the device's own refresh is due (it says
so only at the start of the access), and ~35-40 ns of recovery between accesses. Even an
infinitely fast interface lands at ~80-90 ns in the refresh case, and fixed latency makes every
access that slow. So chip RAM must be in block RAM, and 2 MB (456 tiles) does not fit in the
365 tiles of the XC7A200T.

## The R3 machine

- Chip RAM up to 1 MB in block RAM (256 tiles), served on Minimig's chipset port with the
  same one-clock latency as AExp's original BRAM design. Organised 64 bits wide, so AGA's
  fetch modes (chip48) work: AGA is selectable, with at most 1 MB chip RAM.
- Slow RAM shares that block RAM: chip + slow <= 1 MB (512K chip + 512K slow = the classic
  A500 with trapdoor RAM). It stays on the chip bus, so it is slowed by DMA like on a real A500.
- Kickstart (512 KB, no 1 MB AROS ROM) and up to 4 MB Zorro II Fast RAM in HyperRAM, reached
  through cpu_wrapper's ram* port (the wait-state path the Fast RAM already uses), for the
  68000 as well as the 68020, with a read cache in block RAM. The Kickstart overlay at
  `$000000` after reset goes the same way (Minimig's `ovl` exported to cpu_wrapper).
- HyperRAM layout: 0-2 MB the scaler framebuffer (unchanged), 2-6 MB Zorro II Fast RAM,
  6-6.5 MB Kickstart, rest spare.
- Not on R3: 68040, RTG card, Zorro III RAM, 1 MB Kickstart, HRTmon and AR3, the 68020's
  turbo chip/Kickstart modes (chip RAM via the chip bus, like a real A1200), IDE DMA into
  memory (the sector engine's PIO path stays).

Block RAM: 124.5 tiles today (chipfix-b), minus the 68040 (22) and RTG (3.5) = 99, plus 256
for chip/slow RAM = 355 of 365, plus a few for the CPU cache.

## Implementation (branch `r3`)

- Minimig submodule (branch `r3`): `minimig.v`/`minimig_m65.v` export `kick_ovl`;
  `cpu_wrapper.v` gets `kick_ram`/`kick_ovl`: `sel_kick_hr` sends Kickstart reads (and the
  overlay at `$000000-$07FFFF`) through ram* for every CPU, as bank `1111`.
- `CORE/vhdl/amiga_mem_r3.vhd`: chip/slow block RAM (4 x 16-bit lanes, `chip48`), the
  Kickstart loader into HyperRAM (256 KB mirrored), the CPU port with a 16 KB direct-mapped
  read cache (16-word lines, one-clock hits, critical word first from a fill, write-through,
  the 68000's level handshake and its late write strobes, TG68K's one-clock ready).
- `mega65.vhd`: `amiga_mem_r3` instead of `amiga_sdram` when `G_BOARD = "MEGA65_R3"`; it
  takes the RTG card's HyperRAM path (`main_vram_avm_*` -> CDC FIFO -> write combiner ->
  arbiter); no RTG card, blitter, 68040, Zorro III, cartridges or IDE DMA on R3; chip RAM
  clamped to 1 MB, slow RAM only with 512 KB chip. `main.vhd`: `G_R3` (no 68040 island,
  4 MB Zorro II Fast RAM).
- `top_mega65-r3.vhd`: the Megamiga board-top changes of R4-R6 (SD host bidirectional,
  framebuffer ports, Ethernet, PMOD; the core's SDRAM ports unconnected). `CORE-R3.xpr`
  rebuilt from `CORE-R6.xpr` (only the expected per-board files differ).
- `build_bitstream.tcl`/`reroll_bitstream.tcl`: the SDRAM-only sign-off gates skip R3.
- Menu (`config.vhd`, M2M exception 23 `config-board`): on R3 the 68040, 2 MB chip RAM, the
  Zorro III boards, the graphics card and both cartridges are greyed out, Slow RAM only with
  512 KB chip RAM, and the Fast RAM item reads "Zorro II RAM 4 MB" (same length). R4-R6 get
  the same layout words as before (checked with `~/aexp-work/r3cfg/tb_cfg.vhd`).

Benches:
- `~/aexp-work/r3mem` (`run.sh`, `mut.py`): `amiga_mem_r3` alone - Avalon HyperRAM model with
  random waitrequest/latency/gaps, the Kickstart loader (mirror, reload invalidation), the
  68000 and TG68K handshakes against an independent shadow, the chipset port with `chip48`
  and the scrub. 11/11 mutants killed. Bugs found on the way: a hit on a line whose last
  word was still being written, and (end-to-end) a 68000 write taken before its data strobes.
- `~/aexp-work/r3e2e` (`synth.sh`, `build.sh 0|1`, `run.sh 0|1`): fx68k or TG68K + the real
  `cpu_wrapper.v` + `amiga_mem_r3` (ghdl netlist) + HyperRAM model + chip bus model; a
  Kickstart image boots through the overlay, clears it, checks chip RAM, configures the Fast
  RAM board, tests 64 KB + byte writes + cache-index conflicts + the top of 4 MB + code in
  Fast RAM + a ROM checksum. Both CPUs PASS; the overlay and Kickstart-route mutants of
  `cpu_wrapper.v` fail both.

Builds: `r3-a` (first): WNS +0.152, WHS +0.014, 52.9K LUTs (40 %), 358.5/365 block RAM tiles;
stopped at the sign-off gate (SDRAM-only checks). `r3-b`: stopped by `pal_leg.tcl` (the same
SDRAM-only clock mux). `r3-c` (all of the above + the menu): OK, WNS +0.035, WHS +0.036, PAL leg
setup +6.791 / hold +0.036, 52.9K LUTs, 358.5/365 tiles; `~/aexp-builds/Megamiga-r3-c/mega65_r3.bit`,
checkpoint saved as fedora `~/builds/r3-c-save` (firmware patches: `patch_firmware.sh ... R3`).
The first R6 build of the branch (`r3-r6a`) missed by 5.4 ns: the `if ... generate` labels had
renamed `i_amiga_sdram`/`i_rtg_blitter` (`g_rtg_blitter.i_rtg_blitter`), so CORE.xdc's
constraints matched nothing. The three instances now stay unconditional under their names and
C_HAS_SDRAM selects their outputs (unused on R3, trimmed); only `amiga_mem_r3` is in a generate.
`r3-r6b` (R6, REF chipfix-b): WNS +0.116, WHS +0.004. `r3-d` (R3, REF r3-c): WNS +0.035, WHS
+0.036, the current R3 bitstream (`~/aexp-builds/Megamiga-r3-d`, checkpoint `r3-d-save`).
